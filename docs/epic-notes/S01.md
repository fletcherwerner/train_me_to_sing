# S01 — Spike: local profiles

## What was built
- `src/storage/profileFormat.ts`: zod schema for a profile file (built from the `StoredData` parts), name-to-id rules.
- `scripts/profilesApi.ts`: `handleProfilesRequest(dir, method, url, body)` (plain function, unit tested) and a Connect middleware. Registered in `vite.config.ts` with `apply: 'serve'`, so `vite build` and `vite preview` do not include it. Folder: `profiles/`, or `TMTS_PROFILES_DIR`. Atomic write, 1 MB body limit, ids checked before touching disk.
- `src/storage/profiles.ts`: API client, `isProfilesAvailable()`, `createProfileSync()` (create, load, 500 ms debounced auto-save, flush-before-switch), and `useProfileStatus` for the UI. Loading goes through `importProgress(..., 'replace')`, so `replaceData` keeps the device latency offset.
- UI: Settings → Profiles section; profile name link on Home; a small non-blocking notices bar for "not found" and failed saves.
- `profiles/` is in `.gitignore`.

## Tests
- `scripts/profilesApi.test.ts` (temp folder), `src/storage/profiles.test.ts` (fake API, fake timers), `tests/e2e/profiles.spec.ts`.

## Deviations
- The e2e dev server now runs on port 5174 (was 5173), with `TMTS_PROFILES_DIR` set. A reused hand-started dev server on 5173 has no such variable and the test wrote `ana.json`/`ben.json` into the real `profiles/`.
- Vitest also includes `scripts/**/*.test.ts`.
- The "not found" message uses the stored profile id (`Profile 'ana' was not found`) because the name is only in the missing file.
- Profile ids from names strip non-ASCII letters ("Zoë" becomes `zo`).

## Known issues
- If saving the current profile fails, switching profiles is refused (with the save-failed message) rather than discarding unsaved data.
- A profile saves only while the API is reachable; if the dev server stops, changes stay in the browser and the save-failed message shows.
- Not checked on a phone; profiles are laptop-only by design.
