# E13 — Hardening and polish

## Built

- **Audio recovery (A).** `ensureAudioRunning()` and `watchAudioClock()` in `audioEngine.ts`; the stall decision is the pure `core/session/stallDetector.ts`. Used by the range test (Start, Record and during the countdown), the lesson (Start, each run, and while running), calibration, and the three dev pages that play sound. Fixed wording is in `ui/audioMessages.ts`. A lesson run that ends with the audio clock short of its end is treated as stalled and is not scored. A stalled You do saves nothing and shows no Results.
- **Microphone lost or missing (A3).** `MicPitchSource` listens for the track's `ended` event and maps `NotFoundError` / `OverconstrainedError` to `mic-missing`. The lesson shows "Reconnect microphone" in place of the run button and keeps its step and earlier results. The range test's "Try again" reconnects first; calibration's Retry builds a new source anyway.
- **Test hook.** With `sim=` in the URL, `window.__tmtsTest = { suspendAudio, resumeAudio, loseMic }`. Not defined otherwise.
- **Run-screen layout (B).** Home and title share one header row; the phrase spacer is gone; the graph is `clamp(110px, 15vh, 160px)`; the chip strip is one row that scrolls sideways; chips size to their text; the piano is capped at 110 px high. Results order is header, verdict, score, pass mark, tip, buttons, legend and graph, chips, misses by line, "Missed notes" list. Piano match colour uses the lesson tolerance (`matchCents`). Piano labels are sized from the rendered scale (12 px for "low"/"high" and the edge arrow, 10 px for octave labels, hidden when they would not fit a key). Graph legend added.
- **One look (C).** `.btn`, `.btn--primary`, `.btn--danger`, `.nav-link`, `.page-header` in `index.css`, with CSS variables for light and dark. Home, Settings, Calibrate, Import MIDI, range test, lesson and dev pages use them. Home screen rows, Settings import prompt and developer links, and the Import MIDI form follow section C.
- **Small fixes (D).** `saveData` returns `false` on a throwing `setItem`; the store sets `saveFailed`, shown by `ProfileNotices` and cleared on the next good save. `tsconfig.tsbuildinfo` added to `.gitignore`.

## Deviations from the plan

- `PitchSource` (a shared type in `planning/01-architecture.md`) gained the optional method `onLost?(cb): () => void`.
- S02's graph height (160 px phone, 220 px laptop) is now `clamp(110px, 15vh, 160px)`. `tests/e2e/pitchGraph.spec.ts` asserts 110 to 160.
- The import summary now reads "..., N lessons passed, M attempted"; the earlier unit and e2e assertions were extended, not removed.
- `tsconfig.tsbuildinfo` is still tracked in git: the agent environment refused `git rm --cached`. The `.gitignore` entry is in place; the owner should run `git rm --cached tsconfig.tsbuildinfo`.

## Assumptions

- "One primary per screen state": on the results screen, Try again is primary after a fail; after a pass nothing on the screen is primary (the next step is Home, a link). On the lesson run screen the run button (or Stop, or Reconnect microphone) is the primary.
- The `Needs N semitones` text on Import MIDI and the dev pages is unchanged; only Home rows use "Doesn't fit:".
- The window requirement is checked at 1280×800, 393×852 and 393×660 by resizing the viewport inside one test per lesson.

## Known issues

- Not tried on a real iPhone or with a real microphone or headphones; the sound-stopped and mic-lost paths are covered only with the synthetic source and `AudioContext.suspend()`.
- On very wide ranges (about five octaves or more) the piano on a 393 px phone falls below 80 px high. The test ranges (E2–E4) are well inside this.
