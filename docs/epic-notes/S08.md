# S08 — Accuracy percentage and best score per lesson

## Built

- `src/core/scoring/accuracy.ts` (+ test): `closeness` (1 within 10 cents, linear to 0 at 100 cents, 0 with no pitch), `accuracyOf(ex, frames)` → `{ overall, perNote }` (same note window and scoop allowance as `evaluateAttempt`; every note counts equally), `matchAccuracy` for match targets (frames from the first voiced frame to the end of the matching hold, or the end of the window). Constants at the top of the file.
- `evaluateAttempt` adds `accuracy` to `AttemptResult` and each `NoteResult`; `scoreMatch(outcomes, passScore, accuracies?)` adds `accuracy` to `MatchScore`. Pass/fail is unchanged.
- Storage: optional `bestAccuracy` (0..1) on a lesson's progress (schema, `recordAttempt` = max, `mergeData` = max). No version bump. Profile files carry it through the same schema.
- UI: `BestAccuracy.tsx` (`best-accuracy` line, `results-accuracy` line) used by `Lesson.tsx` and `MatchRun.tsx`; chips show "✓ hit · 94%" (`note-accuracy-<i>`); the notes line is now "2 of 2 notes hit · pass mark 80%".
- Home: "Passed · 91%" / "Best 74%" use `bestAccuracy`. With none (older data): "Passed", "Started".

## Deviations / notes

- `accuracy` is optional on `AttemptResult` and `NoteResult` so hand-built results in older tests still type-check; `evaluateAttempt` and `MatchRun` always set it.
- Profile load uses replace, not merge, so there is nothing extra to take the max of; the field survives because it is in the shared schema (tested).
- The synthetic singer reads the pitch one frame ahead of the recorded time, so `sim=perfect` scores 98–100%, not always exactly 100%. The Playwright spec accepts 98–100% and checks the best equals what the results showed.
- Intro screens show the best-accuracy line under the goal; every other step shows it under the title inside the header (`LessonHeader` takes a `right` slot). A separate line in the page flow pushed the phone run screens of s3-01/s3-04 a few pixels past the window, which `hardening.spec.ts` forbids.
- `hardening.spec.ts` now looks for lower-case "pass mark"; `home.spec.ts` accepts 98–100%.
- "New best" compares whole percents, so equal-looking numbers read "Accuracy: 87% · Best: 87%".

## Known issues

- Results chips grow a little wider with the percentage on a phone; nothing overflows in the specs, but long exercises were not checked by eye.
