# E15 — Daily practice: session, spaced mastery, review, onset coaching

## Built

- **Storage v2** (`src/storage/schema.ts`): progress entries gain `proofs` (`{date, tonicMidi, score}[]`) and `review` (`{step, dueOn} | null`). `storedDataSchema` accepts version 1 or 2 and returns version 2. `migrateProgress` runs wherever data is read: storage load, import file, profile file (`profileFormat.ts`). An entry without `proofs` is a version-1 entry: a passed Stage 2–3 lesson (`s2-*`, `s3-*`) gets one proof `{tonicMidi: -1}` and `passed` becomes false (one more day needed); all others get `proofs: []`, `review: null` and keep `passed`. The localStorage key stays `tmts.v1` so older data is found.
- **Core, pure** (`src/core/progress/`): `mastery.ts` (`isMastered`, `proofTonics`, `addProof`), `review.ts` (1/3/7/14-day steps, `afterReview`, `dueReviews`), `dates.ts` (`YYYY-MM-DD` arithmetic). `core/session/practicePlan.ts`: `planToday`, `describePlan`, `goodSessionNote`. `core/exercise/glides.ts`: the three warm-up glides. `fit.ts`: glide ends count in the span, `tonicCount`, `pickTonic` avoids a list of keys.
- **Store** (`recordAttempt(id, result, level?, ctx?)`): with `ctx.mastery`, a Prove pass (any pass for Stages 2–3) adds a proof for today's date and key; `passed` is set when two days and two keys are met (or one key if only one fits); mastery sets `review` to tomorrow; a later Prove attempt on a due lesson moves the review on or back to step 0. `src/storage/today.ts`: local date, replaced by `?today=YYYY-MM-DD`.
- **Content** (`src/content/mastery.ts`): `usesMastery(lesson)` (built-in melody lessons with levels, and built-in Stages 2–3) and `scoopCountsAsMiss` (Units C–D at Prove).
- **Scoring**: `MissReason` gains `'scooped'`; `NoteResult.scooped`; `onsets.ts isScooped`; `evaluateAttempt(..., {scoopIsMiss})`. Tip "You slid into this note. Try to start right on it." `?sim=scoop` added.
- **Glides**: `TemplateNote.glideToOffset`, `ResolvedNote.glideToMidi`; `tonePlayer.playNote(..., glideToMidi)` ramps the oscillator frequencies; the pitch graph draws sloped target lines (`data-glide`).
- **UI**: `/practice` (`screens/Practice.tsx`, `Warmup.tsx`); Home's Continue card is now "Today's practice" with a summary line; Lesson shows "Passed once — come back tomorrow in a new key" / "Mastered…"; Home rows show "Passed once · NN% — come back tomorrow in a new key" and "Review due". `Lesson.tsx` now exports `LessonRun` (new `forceLevel` prop) which Practice reuses.

## Behaviour notes

- Keys: Practise/Prove pick a new random key avoiding the keys already proved. In `?sim=` runs the key stays centred until the lesson has a proof; then it is chosen deterministically, avoiding proof keys, so the tests can pass in two keys. Stage 2–3 stay centred until they have a proof.
- A second Prove pass on the same day is stored (if in a new key) but counts as the same day.
- Practice parts: Warm-up → Pitch finding (first unpassed Unit A lesson cut to 4 targets, else `s1a-03`) → New pattern (first built-in melody lesson not mastered and without a proof today, at its stored level) → up to 3 due reviews at Prove, else up to 2 random mastered earlier lessons → Wrap-up. The plan is fixed when the screen opens.
- Practice time is the time the screen has been open (wall clock, not musical timing). `?minutes=N` adds N minutes so the 20-minute note can be seen.

## Deviations and assumptions

- Scoop detection needs the voice to start from silence (a null frame or a 100 ms gap) at most 100 ms before the note or inside it; a voice that carries on from the previous note is a leap, not a slide. The first-frame threshold is 70 cents; the pitch must then settle within tolerance within 150 ms of the voice start. Unit A match lessons use their own scoring and have no scoop check. Imported songs and Stages 2–3: tip only (and only where `evaluateAttempt` runs; `scoopIsMiss` is only set for Units C–D at Prove).
- A v1 `passed` Stage 1 unit B–D lesson stays passed with no proofs (the epic gives them `proofs: []`); it has no review until it is passed again.
- Reviews are counted for any Prove attempt (or any attempt, Stages 2–3) made when the review is due, whether from Today's practice or from the lesson list.
- Existing e2e tests that expected a single pass to count (`home`, `stage1`, `stage2`, `stage3`, `profiles`) were updated to expect "Passed once".
- No runtime dependencies added.

## Known issues

- The Pitch finding part saves its 4-target round as the Unit A lesson's attempt, so a Unit A lesson can be passed with 4 targets instead of 5–6.
- Warm-up uses the microphone only to draw the student's line; if the mic is denied the glide still plays.
