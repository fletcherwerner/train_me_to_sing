# E16 — iPhone app with progress saved as a file

## Built

- `src/storage/fileStore.ts`: `FileStore` interface, `capacitorFileStore` (Documents, UTF-8), `createMemoryFileStore`, `getFileStore()` (native → Capacitor; `?filestore=memory` in dev builds only → memory store kept in `sessionStorage['tmts.memfs']` so a reload keeps it; else null).
- `src/storage/fileSync.ts`: after each successful `saveData` in the store's `commit`, queues a write of `StoredData` (2-space JSON) to `progress.json.tmp` then renames over `progress.json`; one write at a time, newest wins; `useFileStatus` (`lastFileSaveAt`, `fileSaveFailed`); daily backup `backups/progress-YYYY-MM-DD.json`, newest 14 kept.
- `src/storage/launch.ts` + `src/main.tsx`: before the app and store load, read `progress.json` (valid wins; missing is created from localStorage; invalid is renamed `progress-unreadable-<date>.json`, replaced, and a Home notice is set). Waits at most 2 s; a late result is ignored. Native only: flush on `appStateChange` inactive.
- Settings file line (`file-save-status`), Home notice (`file-unreadable-notice`).
- Capacitor: `@capacitor/cli` to ^8.6.2, added `@capacitor/filesystem` and `@capacitor/app` (^8). Bundle id `io.github.fletcherwerner.trainmetosing` (config and Debug/Release). `Info.plist`: `UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace`. `docs/ios-build.md` rewritten.

## Deviations

- **`npm run ios:sync` could not run.** Capacitor CLI 8 needs Node >=22; this machine has Node 20 (the same limit E12 recorded). I built `dist` and hand-edited `ios/App/CapApp-SPM/Package.swift` to add the two plugins as local packages (what `cap sync` writes). `ios/App/App/public` and `capacitor.config.json` are git-ignored and regenerated by the sync. The owner should run `npm run ios:sync` on Node 22 and check `git diff ios/App/CapApp-SPM/Package.swift` is empty or trivial.
- `main.tsx` now loads `App` and `profiles` by dynamic import after `launch()`, so the store is created after the file is applied. The web start-up gains one tick; `launch()` returns at once without a file store.
- The unreadable-file notice is a new key (`tmts.notice.fileUnreadable`) in `notices.ts`, shown on Home like the Stage 1 notice.

## Known issues / not verified

- `xcodebuild`, the Simulator build and the device install were not run. The Capacitor `rename` replacing an existing file is untested on a device; `capacitorFileStore.rename` removes the target and retries if the first rename fails.
- File saves are unaffected by profiles (the dev-server profile feature) and by the web build.
